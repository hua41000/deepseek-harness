### TC-01：启用插件后会话出现“花费”页签

- 关联需求：AC-01、FR-01、UI-01
- 前提与数据：DSH Web 按装配方式挂载本插件；界面语言为中文（英文另见 TC-10）；准备一个已有对话的会话和一个新建的空会话。
- 操作步骤：
  1. 打开已有对话的会话，查看会话视图的页签栏。
  2. 点击“花费”页签。
  3. 切换到新建的空会话，再次查看页签栏并点击“花费”。
- 预期结果：
  1. 页签栏中出现“花费”页签，与“对话”“轨迹”“统计”等页签并列。
  2. 进入 UI-01：显示合计卡和每轮明细（内容的正确性由 TC-02 验证）。
  3. 空会话中同样有“花费”页签，进入后显示空状态 C-09。
  4. 页面无脚本错误。
- 验证方式与证据：建议沉淀为 keyless Web e2e（参照 `client-ui-stats-panel.e2e.ts`），保留页签栏和页签内容的 ARIA 快照；真实环境中由 TC-11 再验证一次。

### TC-02：合计卡与每轮明细的金额、模型和一致性

- 关联需求：AC-08、AC-05、FR-02、FR-03、FR-04、BR-01、BR-03（Q-01 已确认）、BR-07、C-05、NFR-03
- 前提与数据：装配本插件；会话包含两轮已完成对话，每轮一步，用量均为样例步骤，开始时间都在北京时间工作日高峰时段。第 1 轮使用 `deepseek-flash`，第 2 轮使用 `deepseek-v4-pro`。
- 操作步骤：
  1. 打开该会话，切换到“花费”页签。
  2. 核对合计卡和明细表；用屏幕阅读器或可访问性树检查明细表列头。
- 预期结果：
  1. 合计卡：估算花费 ¥0.1756，缓存节省 ¥0.9594，模型列出 `deepseek-flash`、`deepseek-v4-pro`，带估算说明 C-06，不出现 C-07。
  2. 明细表按轮次从早到晚两行：#1 花费 ¥0.0316，#2 花费 ¥0.1440；两行的输入均为 100,000 token、输出均为 1,000 token，按 C-05 的大写 `K` / `M` 缩写显示，与统计页签一致（A-07 已确认）。
  3. 各轮花费之和等于合计卡的估算花费。
  4. 列头“轮次、输入、输出、花费”有可访问名称（NFR-03）。
- 验证方式与证据：建议沉淀为 keyless Web e2e，向会话写入两轮带模型和用量的事件并固定时钟；保留 ARIA 快照。

### TC-05：部分加载提示与“加载更早”

- 关联需求：AC-09、FR-07（含共用会话窗口）、C-08、C-12、C-13、UI-01 区域 C 与“加载中”“加载失败”状态
- 前提与数据：装配本插件。一个已持久化的历史会话，轮次足够多，需要**至少三页**历史，使第一次“加载更早”之后仍有未加载的轮次。每轮一步，用量均为样例步骤，模型均为 `deepseek-flash`，时间均在高峰时段；全部 M 轮的合计为 M × ¥0.0316（按 BR-07 显示）。另需一种让“加载更早”请求失败一次的手段（如临时阻断历史请求），由执行者按页面和测试设施确定。
- 操作步骤：
  1. 打开该会话，切换到“花费”页签，记录提示中的 N、合计金额和明细行数。
  2. 点击“加载更早”，观察加载过程。
  3. 加载完成后再次记录 N 和合计；切换到“对话”页签查看最早显示的消息，再切回“花费”。
  4. 让下一次加载失败后点击“加载更早”，观察提示；恢复后点击该提示重试。
  5. 继续点击，直到全部加载。
- 预期结果：
  1. 初次打开：显示“仅统计已加载的 N 轮。”（C-08）和“加载更早”按钮；N 等于已加载步骤涉及、且至少含一步用量记录的轮次数，即明细行数，小于 M；合计等于已加载轮次之和，明细只列出已加载的轮次。
  2. 加载中：显示 C-12“正在加载更早的轮次…”，按钮不可再次点击。
  3. 每次加载后：N 增大，合计金额随之增大，明细增加更早的轮次且仍按从早到晚排列。
  4. 共用窗口：在“花费”页签加载更早轮次后，“对话”页签也显示这些更早的内容（FR-07，A-03 已确认）。
  5. 加载失败：显示 C-13“加载失败，重试”，已显示的合计和明细保持不变；点击后重新加载，成功后结果同第 3 条。
  6. 全部加载后：提示条消失，合计等于全部 M 轮之和，明细共 M 行。
- 验证方式与证据：建议沉淀为 keyless Web e2e（参照 `stats-paged-history.e2e.ts` 的 `seedSession`），每一步保留 N、合计金额和行数；失败重试若 e2e 难以注入，以 T5 视图测试覆盖并在真实环境中人工复核一次。

### TC-06：加载更早后补全模型，未定价减少

- 关联需求：AC-09、FR-07、BR-05（2026-11-13 起明确包含无法确定模型的步骤）、C-08；设计 D-02、D-04
- 前提与数据：装配本插件。历史会话需要至少两页；较早的轮次使用 `deepseek-v4-pro`，之后切换为 `deepseek-flash`，切换发生在初次加载的窗口之内，因此窗口开头有若干步在第一次模型变化记录之前，推不出模型。
- 操作步骤：
  1. 打开会话的“花费”页签，记录 C-07 中的未定价步数和合计。
  2. 点击“加载更早”直到全部加载。
- 预期结果：
  1. 初次打开：窗口开头那些步骤计为未定价，合计卡显示“不含 K 步未定价”，K 等于这些步骤的数量；这些步骤没有模型 ID，不出现在模型列表中（C-04 只列已知模型 ID）。窗口开头若有一轮只加载了部分步骤，该轮计入 C-08 的 N，不额外提示（A-02 已确认）。
  2. 全部加载后：这些步骤按 `deepseek-v4-pro` 计价，C-07 消失，合计增加对应金额。
- 验证方式与证据：keyless Web e2e；这也是风险 R1 的业务证据。

- 验证方式与证据：keyless Web e2e（页面打开后再写入事件）；真实对话由 TC-11 复核。

### TC-08：配置覆盖内置价格并新增模型

  2. #2 花费 ¥0.1130（10,000×2 + 90,000×1 + 1,000×3 = 113,000），不显示“未定价”。

- 验证方式与证据：人工在真实 DSH 中修改配置后观察（AC-07 要求）；可同时沉淀为带配置 overlay 的 keyless Web e2e。

### TC-09：单价配置无效时启动报错，改正后恢复

- 关联需求：AC-15（2026-11-13 细化）、FR-06、UI-01“错误”；设计 D-05、D-09、T8
- 前提与数据：按 README 的方式挂载插件。分别准备三份无效配置，每次只引入一处错误；每份配置的其余部分写全两个时段的 6 个单价（D-06）：
  - 变体 1：`deepseek-flash` 高峰 `output` 为负数（如 -1）。
  - 变体 2：同一字段为非数字字符串（如 `"abc"`）。
  - 变体 3：`deepseek-flash` 的高峰缺少 `output` 字段。
  - 对照变体 0（合法）：`deepseek-flash` 高峰 `{ cacheHit: 0.04, cacheMiss: 2, output: 0 }`，空闲 `{ cacheHit: 0.02, cacheMiss: 1, output: 4 }`；会话中有一轮样例步骤（`deepseek-flash`，高峰）。
- 操作步骤（变体 1～3 各一次）：
  1. 写入该变体后启动 DSH Web。
  2. 查看启动 DSH 的终端日志。
  3. 打开浏览器中的任一会话，查看页签栏和页面（不以开发者工具控制台为判断依据）。
